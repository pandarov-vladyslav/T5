# Flask Authentication Module

Невеликий навчальний REST-модуль реєстрації, входу та виходу користувачів на
Python 3.12, Flask, Werkzeug і SQLite.

## Можливості

- реєстрація користувача з унікальним логіном;
- вхід за логіном і паролем;
- хешування паролів засобами `werkzeug.security`;
- перевірка пароля через `check_password_hash`;
- завершення сеансу через очищення Flask session;
- базова валідація логіна й пароля;
- автоматизовані тести на `pytest`.

Пароль у відкритому вигляді до SQLite не записується. У таблиці зберігається
лише результат `generate_password_hash()`.

## Вимоги

- Python 3.12
- pip

## Запуск

### 1. Створити віртуальне середовище

```bash
python3.12 -m venv .venv
```

Windows:

```powershell
py -3.12 -m venv .venv
.venv\\Scripts\\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

### 2. Встановити залежності

```bash
python -m pip install -r requirements.txt
```

### 3. Встановити секретний ключ Flask

Linux/macOS:

```bash
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
```

Windows PowerShell:

```powershell
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
```

Не використовуйте наведений у тестах ключ у реальному середовищі. Секретний
ключ має бути випадковим, приватним і збереженим у менеджері секретів або
захищених змінних середовища.

### 4. Запустити застосунок

```bash
python app.py
```

Сервер розробки буде доступний за адресою `http://127.0.0.1:5000`.

## API

Усі запити надсилаються з JSON-телом.

### Реєстрація

`POST /auth/register`

```json
{
  "username": "alice_1",
  "password": "a-very-long-password"
}
```

Успішна відповідь: HTTP `201`.

Логін: 3–32 символи, латинські літери, цифри, `_` або `-`.
Пароль: від 12 до 1024 символів.

### Вхід

`POST /auth/login`

```json
{
  "username": "alice_1",
  "password": "a-very-long-password"
}
```

Успішна відповідь: HTTP `200`. Ідентифікатор і логін користувача зберігаються
у підписаній Flask session, яка передається браузером у cookie.

### Вихід

`POST /auth/logout`

Очищає поточну Flask session. Успішна відповідь: HTTP `200`.

## Тестування

```bash
pytest -q
```

Тести використовують тимчасову SQLite-базу даних і не змінюють робочу базу.

## Важливо перед комерційним використанням

Це навчальна основа, а не готова до розгортання система безпеки. Перед
використанням у комерційному вебзастосунку потрібно щонайменше:

- додати CSRF-захист для cookie-based сесій;
- використовувати HTTPS і встановити `SESSION_COOKIE_SECURE=True`;
- додати обмеження частоти спроб входу та моніторинг підозрілої активності;
- не розкривати, чи існує конкретний логін, у сценаріях відновлення доступу;
- додати підтвердження адреси електронної пошти та безпечне відновлення пароля,
  якщо цього потребує продукт;
- налаштувати резервне копіювання, права доступу та міграції бази даних;
- провести перевірку безпеки й тестування в контексті всього застосунку.

Для Flask session застосунок потребує сильного `SECRET_KEY`. Не вмикайте
debug-режим у production. Для production запускайте Flask через відповідний
WSGI-сервер, а не вбудований сервер розробки.

## Ліцензія та походження коду

Код цього навчального прикладу написаний спеціально для цього проєкту.
Скопійовані ліцензійні заголовки або фрагменти невідомого походження не
додаються. Flask, Werkzeug і pytest мають власні ліцензії; перевірте їхні
умови перед включенням залежностей до комерційного продукту.
